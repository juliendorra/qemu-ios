# App-bundle skeleton

`Info.plist.in` is the only part of a `.app` that is neither built nor
Apple-derived, so it is the only part committed here. Everything else in a
packaged bundle comes from somewhere else:

| part | size | where it comes from |
|---|---|---|
| `Contents/Resources` | ~1 GB | firmware + NAND pack (Apple-derived, never committed) and `pc-bios` from the QEMU build |
| `Contents/MacOS/qemu-system-arm` | ~31 MB | built engine |
| `Contents/Frameworks` | ~21 MB | bundled Homebrew dylibs (`install-ipod-app-engine.sh`) |
| `Contents/_CodeSignature` | ~44 MB | generated by `codesign` |
| `Contents/MacOS/iPod Touch` | 8 KB | `scripts/ipod-app-launcher.sh` |
| **`Contents/Info.plist`** | **1 KB** | **this template** |
| `Contents/Resources/AppIcon.icns` | 147 KB | supply your own; `--icon` if you have one |

`scripts/package-iphone-app.sh --create` builds the skeleton from this template
so a bundle can be made without cloning an existing one. `@NAME@` and
`@BUNDLE_ID@` are substituted; pass `--name` / `--bundle-id`.

BUILD.md Part 2 §1 documents the same layout prose-first, for the iPod bundle.
